Version 1.0.5

- Treat the `y'` separator before a vowel-initial fu'ivla as lujvo glue during
  inferred and explicit-source reconstruction. For example, `criny'alga`
  reconstructs from `crino` + `alga` without treating `y'` as a source rafsi.
- Derive the CLI version from the Cargo package version so `--version` reports
  the current release.

----

Version 1.0.4

- Preserve the apostrophe before y after vowel-ending fu'ivla rafsi during
  reconstruction, including diphthongs and compounds with multiple such rafsi.
  For example, `krakatau'yvalsi` reconstructs to `krakatau'yvla`, not
  `krakatauyvla` (which camxes can reinterpret using a u glide).

----

Version 1.0.3

- Reconstruct lujvo containing fu'ivla rafsi through the public reconstruction and
  spelling-analysis APIs. For example, `valsykrakatu` becomes the lower-scoring
  `valykrakatu`. Enable camxes by default so the CLI supports these words.

Version 1.0.2

- Add `reconstruct_fuhivla_lujvo` under the optional `camxes` feature.
  Reconstruct any number of ordered source words with fu'ivla rafsi in any
  position by scoring candidate spellings and validating the camxes parse.
  For example, `tci'ilyfinpe` becomes `tci'ilyfi'e`.
- Split unstressed `y_rafsi` and `hy_rafsi` into rafsi and hyphen segments
  so multi-component source-word lookup preserves component boundaries.

  fu'ivla rafsi from their `y` hyphens for dictionary source-word lookup

Version 0.5

Added candidate evaluation to "gismu_score.py".

When generate candidates with custom shapes, excluding forbidden
consonant triples. Also excluding internal sequences which could be
mistaken for "ccvcv" gismu.

Deduplication and serialization of candidates are now options which are
disabled by default.

----

Version 0.4

Replaced mlpy implementation of LCS (longest common subsequence)
algorithm with a pure-python implementation to simplify
installation and enable compatibility with python implementations
such as pypy and jython.

By default, only generating candidates from letters which appear in input
words. This substantially reduces processing time by avoiding the calculation
of scores for less-relevant candidates.

Added command-line options to "gismu_score.py" to customize language weights,
gismu candidate shape, gismu alphabet, and number of scoring worker threads.

Output of "gismu_score.py" / input of "gismu_best.py" now uses python
"marshal" format due to OutOfMemory errors with pickle/cPickle under
jython.

The gismu candidates DBM database used by previous versions of the script
("candidates.db") is no longer created or consulted.
